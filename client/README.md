# 智能聊天室客户端

打开 **三个 PowerShell 终端**，分别启动 Python 后端、WebSocket 网关和 Vue 页面。

### 1. 启动 Python 后端

在 `agent-chatroom` 仓库根目录运行：

```powershell
python -m server.main
```

看到 `Chatroom listening on ...8765` 就表示后端已启动。默认监听 `127.0.0.1:8765`，并在仓库根目录创建 `chatroom.sqlite3`。

### 2. 启动 WebSocket 网关

在第二个终端进入 `agent-chatroom/client`，运行：

```powershell
npm.cmd run gateway
```

网关默认监听 `8766`，连接后端的 `8765`。如果提示端口已占用，先确认对应终端里是否还开着上次的模拟服务或网关。

### 3. 启动 Vue 并验证

在第三个终端进入 `agent-chatroom/client`，运行：

```powershell
npm.cmd run dev
```

打开**这次 Vite 打印的网址**，使用普通登录页。若地址带 `?demo=1`，请去掉该参数。先注册一个测试账号，再登录。接着开第二个标签页，用**另一个账号**登录，依次检查：

1. 两个账号都出现在对方的在线列表中。
2. 群聊消息两边都能收到，发件人页面只显示一次。
3. 点击在线用户名发私聊，再搜索刚发过的消息。
4. 关闭一个标签页，确认另一边的在线列表更新。
5. 发出 `@Agent 总结刚才的消息`。当前版本缺少正式模型 Runner，预期显示 Agent 失败提示，此后仍能继续发普通消息。


## 无正式后端的本地联调

在 client 目录打开三个终端：

```powershell
npm run mock
npm run gateway
npm run dev:mock
```

每条命令在各自终端运行。模拟 TCP 服务默认使用 127.0.0.1:8765，运行前确保该端口未被其他进程占用。打开 Vite 打印的网址，看到“本地模拟联调”后，用三个浏览器标签页分别注册、登录三个测试账号。测试密码需符合 TCP v1 的 8–128 个 Unicode 字符要求。

- 群聊中发送包含中文、表情和长文本的消息。三人应看到相同消息，发件人只显示一次。
- 在两人间发私聊，第三人应看不到相关消息。关闭接收方页面，发送另一条私聊，重新登录后从历史查看。
- 用同一关键词发送超过 20 条消息，然后搜索并加载更早的消息，验证顺序、去重和滚动位置。缩窄浏览器后，用“会话”按钮切换会话。Enter 发送，Shift+Enter 换行。
- 在群聊或私聊运行总结或待办。工具记录仅发起者可见，回复在会话成员的消息区显示。工具计数来自模拟服务内存中触发前的消息；没有调用真实模型。
- 如需验证失败状态，在启动模拟服务的 PowerShell 终端设置 `$env:MOCK_AGENT_FAILURE = 'unavailable'`、`'tool'` 或 `'timeout'`，再运行 `npm run mock`。超时模式让工具停留在执行中，并在任务执行满 60 秒后发送 `AGENT_TIMEOUT`。普通聊天应继续可用。
- 发送结果待确认时，点“查看历史”会逐页检查发出请求后可能保存的消息。核对完成后，页面显示同内容候选的消息 ID 和服务端时间，再开放重发或取消。

`npm test` 还通过真实网关覆盖断线和请求超时、重登恢复、消息去重、私聊权限，以及 Agent 事件状态和可见范围。模拟数据在服务重启后清空。若只需要预览单人界面，可运行 `npm run demo`。
